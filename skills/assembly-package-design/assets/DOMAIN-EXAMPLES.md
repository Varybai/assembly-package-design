# 跨领域设计起点

下列例子用于填写领域 profile。它们是未实现的设计场景，不是可制造、可部署或已经验证的工程方案。

## 例 1：CAD 夹持模块

目标：复用同一夹持机构，安装在两个不同的机械平台上。

| 决策 | 起点 |
|---|---|
| 原子/模块 | 零件或受控原生子装配/完整夹持机构 |
| 文件 | 原生 CAD 项目为编辑源；STEP 为交换输出；BOM 和预览为派生物 |
| 实例 | 安装坐标、配合、开口参数及平台绑定 |
| 接口 | 安装面/孔、允许载荷方向和适用公差；证据不足项显式未知 |
| 内部检查 | 几何有效性、内部配合和声明的运动范围 |
| 环境检查 | 平台连接、外部干涉、操作空间和系统载荷 |
| 缓存 | 原生依赖、参数、CAD 内核和公差；平台环境另记 |
| Pi 前缀 | `cad_assembly_*`，`/cad-assembly-setup` |

首轮验收：同一模块用于两个位置，一个位置无外部障碍，另一个位置存在干涉。检查应定位到第二个实例。若只实现几何检查，交付不宣称夹持力或实物强度通过。

## 例 2：PCB 电源子电路

目标：在两个主板工程中复用同一个电源子电路，保留原理图和网络关系。

| 决策 | 起点 |
|---|---|
| 原子/模块 | 元件、库符号和封装/有明确输入输出的层级子电路 |
| 文件 | KiCad 原理图、PCB、库表、网表及 BOM；按用途另生成制造输出 |
| 实例 | 独立位号前缀、引脚和网络映射；明确允许共享的电源/地网络 |
| 接口 | 输入电源、输出电源、控制与地；单位、范围和连接规则 |
| 内部检查 | 模块内引用、连通性及适用 ERC；以实际实现为准 |
| 环境检查 | 主板输入条件、负载、网络冲突、层/布局及热环境 |
| 缓存 | 网络/参数/库与规则版本；工况变化使对应结果失效 |
| Pi 前缀 | `pcb_assembly_*`，`/pcb-assembly-setup` |

首版可只完成层级子电路复用、网络映射、ERC 和原生文件交付。布线、DRC、制造与热仿真明确列为后续能力，不能用网表生成成功替代它们。

首轮验收：重复实例化后，两个实例的局部信号网不被意外短接；显式共享的 GND 可以共享。将其中一个实例的输入条件改到声明范围之外，应使该实例不适用，而不是修改另一个实例的定义。这里的电压范围来自实际选定模块资料，本例不指定未经核实的器件能力。

## 例 3：热仿真模型组件

目标：复用同一个几何、材料与网格准备过程，对两个边界条件求解。

| 决策 | 起点 |
|---|---|
| 原子/模块 | 几何区、材料、网格规则和边界定义/可参数化仿真子模型 |
| 文件 | 几何、网格、材料表、求解配置和结果；manifest 固定关联 |
| 实例 | 区域映射、载荷/热源、环境条件和求解器设置 |
| 接口 | 热量、温度、区域或耦合边界，明确单位和约定 |
| 内部检查 | 网格/材料和方程配置一致性 |
| 环境检查 | 边界条件适用性、耦合关系、收敛和系统能量检查 |
| 缓存 | 几何/网格准备可复用；边界条件改变时求解结果重算 |
| Pi 前缀 | `thermal_assembly_*`，`/thermal-assembly-setup` |

首轮验收：改变环境温度时，未受影响的网格准备命中缓存，求解结果失效重算。求解器未收敛时，结果和诊断可以交付，但不能标成已验证的分析结论。使用独立小算例检查方法有效性。

## 例 4：机械、电路和控制组成的系统

目标：组合 CAD 外壳、电路模块和控制配置。

根系统记录各领域固定版本及跨域约束，不把全部文件扁平化成一种“零件”。外壳空间与 PCB 尺寸、电源能力与执行器需求、控制周期与传感器数据率都由显式关系表示。

首轮验收：PCB 版本变化导致厚度或连接器位置改变，应触发相关机械安装检查；仅修改一份说明文档不应强制重算所有工程结果。局部 CAD/ERC/软件测试通过后，系统级适用性仍需单独检查。

优先通过一个明确的集成层组织这些关系。若需要共享 Pi 入口，再设计统一路由器；当前基线不假定该路由器已经存在。
