# 对象、关系与工程文件契约

状态：跨领域设计建议 v0.1。下列对象是逻辑契约，package 可以映射为 JSON、数据库、原生项目文件或其他存储。它们不能直接当作当前 LEGO Registry 的输入。

## 最小对象模型

| 对象 | 必须表达的事实 | 不应承担的职责 |
|---|---|---|
| Definition | 身份、版本、领域、功能、参数、组成、接口、过程及来源 | 保存每次安装环境和运行日志 |
| Instance | 固定定义引用、实例身份、父级、参数与接口/环境绑定 | 覆盖共享定义 |
| Interface | 类型、连接对象、约束、方向及可核查来源 | 仅以名称宣称兼容 |
| Connection | 两端或多端绑定、规则、状态及连接证据 | 把空间邻近自动当成连接 |
| Procedure | 输入、前提、动作依赖、效果、后置检查及副作用范围 | 假设所有领域都只有 place 操作 |
| Artifact | 原生/生成文件、格式、版本、内容哈希、依赖和用途 | 代替功能描述或验证记录 |
| Evidence | 对象、输入快照、方法、条件、结果、范围和产物 | 被当作无条件有效的永久认证 |
| Projection | L0、检索文本、预览、派生摘要及来源引用 | 成为精确几何、电路或仿真的事实源 |

小型实现可把若干对象存于一个文件，但需要保留这些逻辑区别。

## 身份与不可变版本

跨 package 的完整引用应至少固定：`namespace + domain + uid + version`。可另带内容哈希，便于检查引用内容。单项目内部可用短引用，但导出时要能恢复完整身份。

发布后的同一引用必须保持内容不变。草稿可以编辑，但不得冒充固定版本。供应方可以维护“推荐版本”别名；构建快照必须解析为固定版本，不能让 `latest` 漂移进入可复现构建。

定义身份、定义内容哈希和阶段缓存键各有用途。不能把三者混成一个值。语义卡片可独立版本化；若语义存于不可变定义内，修改它也需要新定义版本。编译器可在已证明语义不影响生成结果时复用原编译结果。

参数要声明类型、单位、范围、默认值、枚举或约束，并说明哪些参数改变拓扑。默认值也属于版本化输入。不同参数的实例不得污染其他实例。

## 三种图分别处理

1. **组成图**：定义包含哪些子定义。默认是有限、可展开的有向无环图，可由多个实例共享节点。递归模板应通过显式终止规则展开为有限图，否则拒绝执行。
2. **工程关系图**：电路网络、反馈回路、机械约束、流体连接等。领域允许时可以有环；交给对应检查器或求解器处理。
3. **构建依赖图**：哪些阶段需要哪些产物。调度器通常使用无环图。迭代求解或耦合循环应封装为有收敛条件、上限和结果状态的阶段。

不要把组成图禁止循环的规则直接用于 PCB 回路或控制反馈系统。

## 实例变换由领域定义

通用实例只有“环境中的绑定”概念，不能强制所有领域使用三维位姿。

| 领域 | 可能的实例绑定 |
|---|---|
| 机械/CAD | 坐标系、刚体变换、配合约束、材料和载荷 |
| PCB | 位号命名空间、引脚/网络映射、布局、层和供电条件 |
| 控制/软件 | 信号映射、协议、采样率、执行周期、服务端点 |
| 仿真 | 参数、网格/几何区域、边界条件、求解器配置 |

适配器必须定义变换规则、单位、坐标或命名空间，以及有效性条件。只有声明支持时才允许镜像、缩放、自动改位号或网络重命名。保留原值及变换来源。

## 接口与连接

接口描述应覆盖任务需要的项：

- 稳定接口 ID、类型和 schema 版本。
- 所属对象、子组件/原生文件中的实际绑定。
- 方向、角色、数据类型或物理量。
- 单位、允许范围、公差或协议版本。
- 占用、多连接、排他性和共享规则。
- 条件、来源和验证状态。

机械端口可能需要局部坐标；电路引脚可能需要电压、电流和网络规则；软件接口可能需要消息 schema 与版本。不能要求每种接口都具有所有字段，但领域必须说明缺省和 unknown 的含义。

连接验证至少区分：引用存在、类型可配对、约束满足、环境适用、实际验证。类型兼容也可能受电源、载荷、时序或几何环境限制。跨领域连接必须说明转换、单位和损失假设。

## 多文件 Artifact 契约

一个组件可以对应多个原生文件。文件 manifest 应记录：

```text
artifact_id / role / media_type / format_version
logical_path / content_hash
source_revision / generated_by / input_artifact_refs
dependencies / required_for / optional_or_required
```

路径必须区分包内资源、项目数据、外部库和远程资源。归档路径不得逃出目标目录。外部依赖应固定可核查身份、版本或哈希，并声明访问要求。不得把作者机器上的绝对路径作为发布包的唯一依赖定位方式。

导入器应指定权威输入、可编辑投影和生成输出。原生文件包含未理解的字段时，选择无损保留、明确拒绝或报告有损转换。不得静默删除。往返测试以设计语义是否保留为准；若格式允许变化，还应说明字节变化的原因。

对于时间戳、浮点序列化、随机网格编号等非确定项，定义规范化规则或记录非确定性。没有稳定输入/规范化证据时，不得把相似文件视为可安全共享的缓存对象。

## 功能声明与证据分开

能力声明应说明“在什么条件下，能对什么输入产生什么结果”。证据记录引用对应声明，但不修改历史结果。

推荐验证结果使用 `pass / fail / unknown / skipped / unsupported`，并记录是否执行。声明来源另记为设计者声明、推断或测试观察。当前 LEGO 的 `declared/hypothesis/not_run/observed` 是较简化的表示，迁移时不要把它当作通用可信度排序。

证据必须固定被检查的输入和条件。条件改变时，旧证据仍是历史事实，但可能不再适用。是否可复用由明确的适用性规则决定。
