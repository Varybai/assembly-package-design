# 检索、构建、验证与缓存

对应 C01、C03、C08–C11。以下是设计规则，实际阶段由领域 profile 指定。

## 从需求到候选

```text
任务/功能 → 候选召回 → 精确身份解析 → 约束筛选
→ 接口与环境检查 → 复用、适配或新建 → 构建与证据
```

语义检索、精确编号查询和关系遍历可以组合使用。不能要求已明确编号的任务必须先做一轮宽泛语义搜索。已验证且输入未变的对象可直接复用。

候选选择记录应包含：需求、硬约束、来源、主要候选、排除原因、采用原因和未决项。它证明“为什么在已查候选中采用此方案”，不证明全局最优。未知项保留为未知；降级方案仍需符合用户接受的交付范围。

复用已有模块时，检查适用条件、输入输出、参数范围、外部依赖和证据。模块边界不清晰时保存历史；提取操作应保留选择范围、原步骤、原始来源、局部变换以及尚未解析的外部依赖。

## Procedure 的执行契约

每类操作应声明输入 schema、前置条件、读写集合、效果、后置检查及失败行为。动作可以是创建、放置、连接、映射、生成网格、求解、导出等；具体名称由领域适配器提供。

可计算的规则由代码检查；需要人工判断的条件明确列为人工/外部证据。仅把约束写成一句自然语言不等于程序已执行该检查。

对数字设计，应使用快照、临时工作区、版本检查和提交记录，避免失败后覆盖原工程。对实物设备、外部服务或不可逆动作，记录已发生的效果及补偿/恢复方法；不得许诺通用回滚。

重试策略按动作副作用设计。纯计算可按输入键重试；有外部副作用的动作需要幂等键、去重或明确恢复路径。取消后保留已完成产物和状态，终止属于该次调用的工作，不影响无关任务。

## 阶段依赖与交付状态

示例阶段：导入→解析→实例化→生成→内部检查→系统环境检查→输出→预览/说明→打包。实际顺序可以不同，例如网表检查在布局之前、制造 DRC 在布线之后、耦合仿真在完整系统绑定之后。

领域 profile 为每项交付声明必要阶段和验证门槛。只有这些条件满足，才可标记为该用途的完成状态。

| 情形 | 应报告的状态 |
|---|---|
| 数据已生成，后续阶段还在执行 | 明确哪些产物已 ready，哪些仍 running |
| 必要阶段和约定检查通过 | 对约定用途 complete，并保留范围说明 |
| 可选预览/说明失败 | 降级交付已有合格产物，列出限制 |
| 必要求解失败或必要检查不通过 | failed/validation_failed；可交付诊断草稿，不能标成合格输出 |
| 缺少外部能力/文件 | blocked/unsupported，列出受影响阶段和独立可交付部分 |
| 用户取消 | cancelled，并说明已完成产物及实际副作用 |

以上状态名是建议；领域可以映射为自己的枚举，但语义不得混淆。日志中的旧 `running` 记录不能单独证明进程仍存活。

浏览器研究和 native viewer 默认属于独立任务。某个专有格式必须由 GUI 导出时，明确这个真实依赖；锁屏后标明该导出阶段受阻，并交付其他已经完成的部分。机器睡眠造成的进程暂停不属于渲染器超时机制能消除的问题。

## 两类验证

**模块内部验证**检查固定模块内部的事实。例如局部连通性、约束一致性、接口存在、网表规则或局部几何关系。

**实例环境验证**检查模块在具体系统中是否适用。例如空间干涉、总线冲突、供电余量、系统载荷、边界条件和时序。

内部检查结果应携带前提。若新环境改变这些前提，必须重算受影响的内部结果。例如一个稳压模块在 12 V 输入下的温升结果，不能直接用于 24 V 环境。

父级可复用已覆盖的子级内部检查，但还要检查跨模块关系和系统属性。四个局部通过的模块，不自动组成一个通过的系统。

## Evidence 最小记录

```text
evidence_id
subject_definition_or_instance
input_manifest_hash / scene_or_environment_revision
claim_or_requirement
checker_or_solver_id + version + configuration
assumptions / scope / tolerances
result + reason + executed
output_artifacts + hashes
recorded_at / applicability_rule
```

时间字段用于追溯，不应默认加入所有缓存键。时效本身会影响有效性的检查，应把时效策略列为输入。数值公差、随机种子、网格策略及求解器版本可能改变结论，必须按实际因果关系处理。

## 分阶段缓存契约

| 缓存层 | 典型必要输入 |
|---|---|
| 解析 | 原生文件及依赖闭包、解析器版本、单位/格式解释策略 |
| 编译/生成 | 固定定义、影响结构的参数、子结果、生成器及相关环境 |
| 内部验证 | 编译结果、检查器、阈值、公差和适用条件 |
| 环境验证 | 实例绑定、相关外部状态、检查器及其邻域/影响范围规则 |
| 仿真 | 系统输入、边界条件、材料、网格、求解器、种子/收敛设置 |
| 渲染/说明 | 对应模型、视图、材料、字体、说明内容和生成器 |
| 打包 | 明确的产物 manifest、交付策略与打包版本 |

仅影响文字的修改，可以只使检索投影或说明失效，但需证明它未参与生成算法。改变一个实例应尽量只重算受影响部分。影响范围由领域决定：电气网络可能是全局依赖，不能照搬机械空间邻域筛选。

缓存写入需要完整性检查和原子提交/等效机制。并发构建不能暴露半成品。缓存损坏按 miss 重建。版本、许可、租户或访问边界不允许共享时，即使内容相同也不能跨边界复用缓存。

## 性能记录

分别记录 Agent 检索/规划成本、确定性计算、验证、渲染和打包耗时。比较冷构建、热构建、移动单实例、修改内部参数和变更求解器等场景。注明数据规模、机器、版本、缓存范围和未清除的外部缓存。

当前 LEGO 的单次加速比不能用作其他领域的承诺。缓存命中率也不能证明设计质量或物理正确性。
