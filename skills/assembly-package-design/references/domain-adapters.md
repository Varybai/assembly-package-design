# 通用内核与领域适配

通用层组织身份、组合、流程和证据。领域层解释真实工程语义。可以先用统一设计方法配合独立实现；不要求先写一个支持所有领域的运行内核。

## 共性与差异

| 可沿用的通用决定 | 由领域 profile 决定 |
|---|---|
| 功能描述与精确身份分离 | 功能词、单位、类别和能力谓词 |
| 定义/实例/运行分离，固定依赖 | 什么是原子对象，如何实例化和重命名 |
| 分层访问、候选与证据分离 | 有效接口、连接规则、参数和工况 |
| 构建记录、产物 manifest、阶段状态 | 解析器、文件格式、生成器和求解器 |
| 因果依赖缓存、失败恢复、取消 | 影响范围、数值公差、时效与失效条件 |
| Pi 工具与 Skill 分工，项目数据隔离 | 工具前缀、支持平台、依赖和 setup 方法 |

当前 LEGO 的 3×3 旋转、LDraw 色号、`.dat`、`place` 和 AABB 都属于右栏，不作为其他领域的默认事实。

## 领域适配器应回答的问题

1. **导入/导出**：哪些原生文件可读写？哪个版本？哪些字段理解、保留或拒绝？
2. **对象解析**：怎样取得固定身份、组件、接口、依赖和来源？
3. **实例化**：如何处理坐标、位号、网络、资源名称和参数？
4. **组合**：哪些接口可连接？哪些关系允许循环？需要何种求解？
5. **执行**：支持哪些动作、前提和效果？发生副作用后如何恢复？
6. **验证**：哪些是内部检查，哪些必须在系统环境中检查？
7. **交付**：哪些阶段是目标用途的必要条件？哪些只是可选预览？
8. **缓存**：每个结果依赖什么？领域影响范围如何判定？

可以把这些能力实现为库、CLI、本地进程或服务。需要稳定输入输出、能力声明、版本和错误语义。没有实现的能力显式返回 unsupported；不能仅靠 Skill 提示补足求解器。

## 多领域映射

| 领域 | 原子对象/组合体示例 | 原生文件示例 | 实例与接口重点 | 必要领域检查示例 |
|---|---|---|---|---|
| LEGO | 零件/轮组、涡轮展示模块 | DAT、LDR、MPD | 刚体位姿、连接点、库存 | 引用、连接、干涉、支撑；按实际能力声明 |
| 机械/CAD | 零件/传动或夹持组件 | STEP、FCStd、原生装配文件、BOM | 坐标、配合、公差、材料、载荷 | 几何有效性、配合可解、运动包络、强度 |
| PCB | 元件/稳压或传感器接口电路 | KiCad schematic/PCB、库、网表、BOM、Gerber | 位号、引脚、网络、层、电源域 | ERC、DRC、网络绑定、供电/热条件；制造规则 |
| 控制/机器人 | 控制块/闭环或执行机构子系统 | URDF、配置、模型图、代码、参数文件 | 单位、信号、坐标、采样率和延迟 | 接口/时序、约束、稳定性或仿真；按用途定义 |
| CAE/仿真 | 几何区/网格与边界条件模型 | 网格、材料、求解配置、结果文件 | 区域映射、单位、边界和求解器 | 网格质量、方程/条件一致、收敛、独立算例对照 |
| 混合工程系统 | 机械结构+PCB+控制软件 | 各领域原生文件与系统 manifest | 共同版本快照、跨域接口和假设 | 跨域尺寸/功率/热/时序约束与系统集成 |

这张表给出设计问题，不表示当前包已经支持列出的格式或验证。不能把“拥有文件扩展名”当作“能够处理该格式”。

## 跨领域复用的边界

整机可以引用多个领域模块，但每个引用保留原领域契约。跨域适配器说明输入、输出、单位、近似模型和验证。例如把电路功耗传给热模型，需要明确工况和功耗分布；不能只复制一个数值。

多个验证结果的组合必须有系统级论证。机械空间通过与电路 ERC 通过，不能自动证明散热、振动或电磁兼容通过。

## 从当前实现迁移

可优先复用的机制包括：目录与版本管理、按需展开、内容寻址、构建阶段记录、项目路径隔离、Pi 生命周期和安装测试。

需要重新设计的机制包括：零件解析、接口类型、实例变换、操作集合、约束求解、环境影响范围、输出格式和交付门槛。复用代码前检查实际耦合，不能只按文件名判断它已通用。

例如当前 `Compiler` 把层级展开成 LDraw 零件，`validation.py` 使用 AABB，`render.py` 调用 LeoCAD。PCB 包不能直接继承这些语义。先实现一个受控小电路的本领域闭环，再比较哪些目录、缓存和宿主机制值得共用。
