# 实施与验收规范

这些用例供新领域选择和具体化，不是一个已经运行的跨领域测试套件。每个 package 必须报告哪些用例适用、实际运行结果及未覆盖内容。只检查文档存在，不等于工程能力通过。

## 最小实施闭环

从一个小型但真实的领域对象开始：导入/定义→两处复用→内部验证→环境验证→原生输出→可检查记录。至少设置一个应该成功和一个应该失败/未知的场景。

先证明领域语义，再扩大格式、模块数或并行规模。不要先用 LEGO 的坐标与 AABB 替代目标领域的有效性检查。

## 可复用验收用例

| ID | 要检查的行为 | 预期结果 |
|---|---|---|
| A01 身份 | 同 UID/版本提交不同内容；固定版本重新加载 | 冲突拒绝；旧内容不变且可解析 |
| A02 实例隔离 | 同一定义实例化两次，修改一个实例绑定 | 另一个实例及共享定义不变 |
| A03 依赖闭包 | 缺少子定义、外部文件或不允许的组成循环 | 明确拒绝，不偷偷替换为默认对象 |
| A04 关系图 | 合法反馈/网络回路与非法构建依赖环 | 由正确规则处理，不把全部图统一禁止环 |
| A05 接口 | 形状/名称相同但单位、协议或工况不同 | 拒绝或转入明确适配；未知不当通过 |
| A06 层次访问 | 大模块逐层展开，原子件终止，分页继续 | 引用稳定、上下文有界、无伪造物理分页模块 |
| A07 文件往返 | 导入并导出多文件项目，包含未知但可保留字段 | 保留设计语义/依赖；有损内容被明确报告 |
| A08 内外检查 | 两处复用，只有一个环境不满足前提 | 内部适用证据复用；失败归到正确实例 |
| A09 系统属性 | 子模块各自通过，但总体违反功率/载荷/时序约束 | 系统检查失败，不从局部结论推导整体通过 |
| A10 缓存 | 原输入重跑；改参数、外部条件、文件和工具版本 | 相同输入复用；因果相关结果正确失效 |
| A11 不相关修改 | 只改不影响生成的说明，或领域证明无关的环境 | 可复用相关计算；不误用未证明的忽略规则 |
| A12 证据 | 输入/工况改变后请求旧证据 | 保留历史结果，判定不适用或重算 |
| A13 执行失败 | 在产生部分文件后失败；旧工程存在 | 旧工程不被半成品覆盖，部分结果可定位 |
| A14 副作用 | 重试或取消具有副作用的动作 | 无重复执行，或准确报告已执行效果及恢复方法 |
| A15 交付门槛 | 必要求解失败与可选渲染失败各一次 | 两者状态不同；不合格产物不标为可制造/可部署 |
| A16 无 GUI | 图形界面不可用或渲染进程挂起 | 可独立阶段继续交付；必要 GUI 阶段明确受阻 |
| A17 Pi 生命周期 | 仅发现资源、执行、取消、shutdown | 加载不启动长任务；取消/退出清理自有资源 |
| A18 安装隔离 | 新目录安装/更新/卸载，原数据已有内容 | 路径可移植；旧数据不丢失；无隐式全局变更 |
| A19 多包共存 | 两个领域包同时安装并调用 | 无工具名、提示区块、配置、缓存或输出冲突 |
| A20 原生错误 | 参数错误、后端失败、工具缺失 | Pi 收到原生失败或明确 unsupported，而非成功文本 |

不要强制每个小包实现所有工程求解。若某个用例不适用，说明领域范围；若应适用但没有能力，记录为未实现，缩小可承诺的用途。

## 证据分层

| 证据 | 能支持的结论 |
|---|---|
| schema/静态检查 | 数据契约符合已写出的规则 |
| 单元与夹具测试 | 已覆盖输入下的算法行为 |
| 真实宿主与离线 provider | 工具注册、Skill 读取、参数与错误传输、执行链 |
| 真实原生工具/求解器 | 指定版本和工况下的文件处理或求解行为 |
| 独立算例/交叉工具对照 | 在对应范围内增强结果可信度 |
| 实物/现场验证 | 指定设备、条件与测量方法下的实际表现 |

这些证据没有自动传递关系。一个层级的成功不能替代另一个层级要求的证据。

## 每个新包应交付的设计材料

- 使用场景、非目标、基线版本和领域 profile。
- 权威文件与对象/接口/程序契约。
- 必要交付阶段、验证范围、缓存键和失效条件。
- Pi manifest、命名空间、安装/setup/迁移方案。
- 至少一个成功和一个失败/未知的验收场景。
- 已实现、部分实现、未实现和已验证状态；偏离规则的决策记录。

实际测试报告要含输入版本、环境、运行命令、结果与产物路径。性能报告分别列冷/热及变更场景，不用旧模型的加速比代替新领域测试。
